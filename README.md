# InsightFlow Store

**InsightFlow Store** is an Android telemetry generation and testing application designed to produce authentic, real-world Google Analytics 4 (GA4) / Firebase Analytics event streams for training and validating the **InsightFlowAI** machine learning models.

---

## 🎯 Consolidated Features & Telemetry Capabilities

1. **Interactive E-Commerce Experience:**
   - Realistic product catalog across Audio, Phones, Wearables, Computing, and Accessories.
   - Dynamic Cart with real-time subtotal, item counts, and coupon code support (`SAVE10`, `SAVE25`, `HALFPRICE`).
   - Multi-step checkout with address details, payment method selection, and order completion.

2. **Standard GA4 E-Commerce Telemetry & Payload Validation:**
   Dispatches standard GA4 e-commerce events with full parameter bundles and strict client-side validation (`EcommerceValidator`):
   - `view_item_list` (includes list name, list ID, and validated item bundles)
   - `view_item` (validated product ID, name, category, and positive price)
   - `add_to_cart` / `remove_from_cart` (validated item & quantity >= 1)
   - `view_cart` / `begin_checkout` / `add_shipping_info` / `add_payment_info` (validated items & totals)
   - `purchase` (validated `transaction_id`, reconciled total `value`, order `discount`, `coupon`, and proportional item-level discount allocations)
   - **Validation Safety:** Invalid or malformed events log a warning `⚠️ SKIPPED` in the live telemetry stream rather than crashing or sending corrupt data to GA4.

3. **Revenue Reconciliation & Discount Allocation:**
   - **Post-Discount Item Prices & Scope:** Order discounts are proportionally allocated across items (`EcommerceValidator.allocateDiscounts()`).
   - **No-Tax / No-Shipping Model:** Ensures exact mathematical reconciliation: `subtotal - discountAmount == totalAmount`, and post-discount item sum matches the net purchase `value`.

4. **Chaos & Scenario Injector (AI Simulator):**
   Tap the **AI** icon in the top app bar to open the live simulator. Choose a target condition and run automated user sessions:
   - `NORMAL`: Organic browsing with calibrated ~3% end-to-end conversion (`addToCart` 25% × `beginCheckout` 40% × `purchase` 30% = 3.0%).
   - `TRAFFIC_DECLINE`: Reduced visit volume (~2.6% conversion).
   - `CONVERSION_REGRESSION`: High cart additions followed by heavy checkout abandonment (~1.0% conversion).
   - `AOV_DECLINE`: Purchasing low-value items with 50% discount codes (~6.0% conversion).
   - `CHECKOUT_REGRESSION`: Users entering payment but failing/aborting at checkout (~0.6% conversion).
   - `GLOBAL_ANOMALY`: Multi-metric breakdown (~0.1% conversion).

5. **Simulation Run Manifest & Provenance Tracking:**
   - **Local Run Manifest:** Persists every simulation run locally (`runId`, `scenarioCode`, `targetClassIndex`, `seed`, `requestedSessions`, `completedSessions`, `startTimestamp`, `endTimestamp`, and `status`: `RUNNING`, `COMPLETED`, `CANCELLED`, `FAILED`). Retains the 100 most recent runs with safe JSON parsing.
   - **GA4 High-Cardinality Cleanliness:** Excludes high-cardinality `runId` from GA4 event payloads to protect reporting cleanliness. Attaches low-cardinality parameters (`scenario_code`, `target_class`, `is_synthetic = 1`) to GA4 events.
   - **Seeded Execution & Cancellation Guard:** Supports custom integer/long seeds for 100% deterministic, reproducible scenario execution. Prevents starting new simulations while cancellation cleanup is active.

6. **Live Telemetry & Manifest Drawer UI:**
   Toggle between real-time outgoing event logs and local simulation run manifest history directly inside the app.

## 🚀 Getting Started

### 1. Connect to your Firebase / GA4 Property
1. Go to the [Firebase Console](https://console.firebase.google.com/).
2. Create or select your Firebase project and enable Google Analytics.
3. Add an Android app with package name:
   ```
   com.cex.insightflowstore
   ```
4. Download `google-services.json` and place it in the `app/` folder:
   ```
   InsightFlowStore/app/google-services.json
   ```
   *(Note: The build automatically detects this file and applies the `com.google.gms.google-services` plugin).*

### 2. Build, Test and Run
Open this project in Android Studio or build and run unit tests via command line:
```bash
./gradlew testDebugUnitTest
./gradlew assembleDebug
```

## 📊 Mapping to InsightFlowAI 6-Feature Model

The events generated by this app directly map to the 6 normalized features expected by `insightflow_model.py`:

| Model Feature | GA4 Source Telemetry | Metric Calculation & Definition |
| :--- | :--- | :--- |
| `userChange` | Active Users / Sessions | Relative change in total active session volume across window |
| `purchaseChange` | `purchase` Event Count | Count of valid `purchase` events |
| `revenueChange` | `purchase` Event `value` | Sum of net purchase `value` (reconciled after discounts) |
| `conversionChange` | `purchase` / Total Sessions | Ratio of `purchase` events to total simulated sessions |
| `checkoutConversionChange` | `purchase` / `begin_checkout` | Ratio of `purchase` events to `begin_checkout` events |
| `cartAbandonmentChange` | `add_to_cart` Abandonment | Ratio of sessions with `add_to_cart` that did not reach `begin_checkout` or `purchase` |

### 💡 Important Metric Interpretation Notes:
* **Simulator Sessions vs. Independent GA4 Users:**
  Automated simulation runs execute on a single device / app instance ID. In standard GA4 reports, sessions on the same device share the same App Instance ID. Therefore, simulator sessions cannot be treated as 1:1 independent human users in user-level deduplication metrics. Instead, training telemetry relies on session-level event count ratios.
* **Event-Count Ratios vs. User-Level Funnels:**
  User-scoped funnels in GA4 require unique `user_id` tracking across sessions. For synthetic scenario injection, event-count ratios (e.g. `purchase / begin_checkout` or `add_to_cart / view_item`) provide clean, reproducible signals for model anomaly classification without relying on artificial user ID synthesis.
